# AICoach 当前实施计划

## 目标

先把配置中心整理成能正常维护意图识别规则的页面，再继续完善识别和观测页面。

## 配置中心有什么作用

| 配置 | 作用 |
|---|---|
| Route | 一级分类。固定为系统已有的 7 个 Route。 |
| Intent | 二级分类，必须归属某个 Route。模型识别结果中的 `intents` 来自这里。 |
| Slot | 定义需要从用户输入中提取的参数，例如身体部位、训练目标。 |
| Enum | 限制 Slot 的可用值，并配置标准值、中文名和别名。例如把“膝盖”“膝关节”统一为 `knee`。 |
| Example | 给模型提供分类示例，帮助模型理解 Route 和 Intent 的边界。 |
| Prompt | 规定模型如何分类、如何输出 JSON、需要遵守哪些规则。 |
| Draft | 正在编辑、尚未上线的配置。 |
| Validate | 检查 Route、Intent、Slot、Enum、Example 之间是否存在错误引用或冲突。 |
| Preview | 查看当前配置最终会生成什么提示词。 |
| Release | 将验证后的配置发布为不可修改的正式版本，供 Runtime 使用。 |

模型地址、API Key、默认模型不属于配置中心，继续由“模型管理”负责。

## 执行顺序

### 1. 整理配置中心

- 拆成左侧分级目录：
  - 意图管理：Route 管理、Intent 管理。
  - 参数管理：Slot 管理、Enum / Alias 管理。
  - 样例管理、提示词管理、发布管理直接作为页面入口。
- 包含多个页面的目录可以展开、收起；单页面不增加无意义层级。
- 每个二级页面使用独立 URL，不再堆在同一个 Tab 页面。
- 用表单替代主要 JSON 编辑框。
- 一级 Route 只读展示，不允许新增、删除、改名或禁用。
- 在每个 Route 下管理二级 Intent。
- 独立管理 Slot 和 Enum。
- 独立管理 Example。
- 独立管理 Prompt。
- 保留校验、Prompt 预览、发布和历史 Release。
- 配置错误直接标出具体字段和原因。

### 2. 补齐当前业务配置

- 检查现有 Intent 是否完整归属正确 Route。
- 检查 Slot 与 Enum 的关系。
- 处理 `body_part` 缺少“腰/腰部”等实际值的问题。
- 校验通过后发布新的 Active Release。

### 3. 完善意图识别页面

- 明确显示一级 Route。
- 将当前“意图”改为“二级 Intent”。
- 显示 Intent confidence、Slot、Risk、Clarification。
- 增加可折叠的结果 JSON 和复制按钮。
- 失败时保留输入并显示具体错误。

### 4. 人工验证完整链路

```text
配置中心发布
→ 选择模型
→ 输入文本
→ 返回一级 Route
→ 返回二级 Intent
→ 展示 Slot 和结果 JSON
```

### 5. 整理调用观测页面

- Trace 列表清楚显示时间、状态、模型、Route 和耗时。
- 详情分开显示结果、Prompt、请求、响应、重试和错误。
- JSON 使用代码视图，不再直接堆整页文本。
