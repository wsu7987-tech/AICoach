# 07 数据库与配置版本设计

## 1. 当前原则

业务配置与模型运行配置分离：

- `ConfigRelease` 只冻结 Route、Intent、Slot、Enum、Example 和 Prompt 等业务规则；
- `ManagedModel` 管理模型地址、模型名、调用参数和加密凭据；
- `RuntimeModelState` 保存默认模型；请求也可以显式指定 `model_uid`；
- 发布业务配置不会切换模型，切换默认模型也不会创建业务 Release；
- 页面默认不展示数据库 ID、Hash、Fingerprint 或原始 JSON。

MySQL 使用 `utf8mb4`。配置快照采用少表、不可变 Snapshot 设计。

## 2. 核心表

### config_draft

单例草稿，包含：

- `schema_version`
- `draft_json`
- `updated_by / updated_at`

`draft_json` 顶层严格包含
`schema_version/routes/intents/slots/enums/examples/prompt_template`。

### provider_credential

- `credential_uid`
- `encrypted_secret`：应用层认证加密后的密文
- `secret_hint`：仅用于遮罩显示
- `key_version`
- `last_verified_at / created_at / updated_at`

主加密密钥只由部署环境提供，不进入数据库、API 响应、日志或 Trace。查询接口不得返回
密文或解密后的 Secret。

### managed_model

- `model_uid = "mdl_" + SHA256(normalized(base_url) + "\n" + model_name)`
- `display_name`
- `provider`：内部协议适配器，一期固定为 `openai_compatible`
- `model_name / base_url`
- `credential_id`：必填且唯一，指向 `provider_credential`
- `params_json / timeout_seconds / max_retries / max_concurrency`
- `enabled / created_at / updated_at`

`model_name + normalized(base_url)` 是模型身份，创建后不可改；API Key、显示名称和调用参数
不参与身份。模型参数可以更新，每次调用仍保存当时实际使用的非 Secret 快照。

不再支持 `credential_ref` 或旧环境变量凭据回退。

### runtime_model_state

单例：

- `default_model_id`
- `updated_at`

默认模型不属于模型身份。切换默认模型不创建模型、不发布业务配置；当前默认模型禁止直接禁用。

### config_release

- `id / version`
- `snapshot_json`：仅 Business Config Snapshot
- `config_snapshot_hash`：服务端完整性校验字段
- `note`
- `created_by / created_at`

历史行不可修改或删除。`version` 是面向产品的 `config-vN`；数据库 ID 和 Hash 不在默认页面展示。

### runtime_state

单例：

- `active_release_id`
- `updated_at`

发布事务先写入不可变 Release，再原子更新 Active 指针。

### intent_request_trace

请求级记录：

- `trace_id / request_id / parent_trace_id`
- `source / input / context`
- `release_id / config_snapshot_hash`
- `managed_model_uid / managed_model_snapshot_json`
- 结果、证据、校验、时间线、耗时、Token、重试、状态和错误

模型快照不包含凭据或凭据标识。

### llm_call_trace

Attempt 级记录 Provider、模型名、参数、Prompt、请求/响应、解析结果、Token、耗时与错误。
唯一键为 `(trace_id, attempt_no)`；Raw 字段受大小限制并记录截断标记。

### evaluation_dataset / evaluation_run / evaluation_case_result

Evaluation Run 冻结：

- Dataset Hash
- `release_id / config_snapshot_hash`
- `managed_model_uid / managed_model_snapshot_json`
- repeat、worker concurrency 和执行状态

V2 评测还保存 `cases_json`、`config_snapshot_json`、`evaluation_config_json`，包含独立评审模型、
凭据密文摘要、评审 Prompt、规则/代码版本和验收阈值。结果增加自动判定和追加式复核历史。
`0006_evaluation_v2` 清空旧评测数据后增加这些字段；不兼容旧评测语义。
详见 [批量评测使用与验收](12-批量评测使用与验收.md)。

Case Result 保存 expected、actual、passed、error、request/trace 和 latency。

## 3. 配置发布

```text
Draft validate
-> canonicalize business JSON
-> create immutable ConfigRelease
-> transaction switch runtime_state.active_release_id
-> Runtime cache eventually refreshes within TTL
```

发布请求只包含发布说明与 Draft/Active 并发校验令牌，不接受模型字段。

## 4. 历史恢复

```text
historical release
-> copy business snapshot to Draft
-> optional edit
-> validate
-> publish as a new release
```

不直接修改历史 Release，也不把 Active 指针切回旧行而跳过发布说明。

## 5. Bootstrap 与首次上线

`bootstrap/initial-config.v1.json` 仅用于首次创建 Draft，不自动创建模型或发布。

首次上线顺序：

1. 执行 migration；
2. 导入 Bootstrap 到 Draft；
3. 创建并验证 ManagedModel，设置默认模型；
4. 校验 Draft；
5. 发布首个业务配置版本；
6. `/api/admin/status/summary.runtime_config_ready` 变为 true。

`/ready` 只检查服务面和数据库 Schema，不等待首个模型或 Release。

## 6. 旧 ModelConfig 移除迁移

`0005_remove_legacy_model_config` 是经产品确认的破坏性迁移，不做历史兼容：

- 清空旧 ConfigRelease、Intent/LLM Trace、Evaluation Run/Case 数据；
- 删除 `model_config` 表；
- 删除 Release、Trace、Evaluation 上的旧模型绑定、Hash 和 Fingerprint 字段；
- 删除仍依赖 `credential_ref` 或没有加密 Credential 的 ManagedModel；
- 删除孤立 Credential，并移除 `managed_model.credential_ref`；
- 为 Trace 和 Evaluation 增加 ManagedModel UID 与快照字段；
- 保留业务 Draft 和已使用加密 Credential 的 ManagedModel。

该迁移不可 downgrade；如需恢复历史，只能使用执行迁移前的数据库备份。

## 7. 模型生命周期

- 模型身份字段不可原地修改；需要更换 `model_name/base_url` 时创建新模型；
- API Key 可替换，调用参数与显示名称可编辑；
- 禁用模型不能成为默认模型或被新请求选择；
- 当前默认模型必须先切换后才能禁用；
- 一期不物理删除 ManagedModel，历史 Trace 使用已保存的非 Secret 快照解释。

## 8. 索引与保留

Trace/Run 至少按 `created_at`、`status`、`release_id`、`managed_model_uid` 和业务查询字段建立索引。
Trace 支持 Raw 大小限制、截断标记、请求与 Attempt 级联清理，以及普通/评测 Trace 的独立保留周期。
