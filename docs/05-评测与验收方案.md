# 05 评测与验收方案

当前评测以 V2 多动作识别结果为准，原 TASK-301 仅作为参考。完整规范见 [批量评测使用与验收](12-批量评测使用与验收.md)。

## 输入与流程

模板为 `assets/AI_Coach_批量评测模板.xlsx`，必填问题、标准答案；支持页面编辑。
可选填写标签、关键用例、动作、参数、依赖、风险和追问的精确要求。

```text
问题与标准答案 → 不可变评测集 → 冻结业务配置/模型的 Run
  → MySQL Worker → V2 IntentService → 精确规则 → 模型评审或人工复核
  → 最终通过率 → badcase 筛选/导出 → 新任务复测与同集对比
```

## 主要约束

- 所有 Route 按明确标注检查，不保留训练业务统一豁免。
- 单意图和复合意图使用同一结构；并行动作一对一匹配，顺序/依赖核对。
- 未填写表示不检查，显式空值才表示期望为空。
- 自然语言标准可选模型评审，输出 PASS/FAIL/REVIEW；未选模型由人工复核。
- 明确规则失败不能覆盖，修正标准答案须保存数据集新版本。
- 主通过率为每条首次执行最终通过数 / 全部用例数，执行错误保留在分母。
- repeat 附加结果用于稳定性；全部执行和复核结束才形成最终验收结论。
- 关键用例任何重复未通过，或未达到创建时确定的阈值，均不达标。
- 同集对比要求相同内容 hash 和规则版本，评审模型变化显式提示。
- 结果独立持久保存，Trace 过期不丢结果。任务恢复由领取 token 和唯一结果键保护。
