# 05 评测与验收方案

## 1. 目标

批量验证生产 `IntentService`，形成可回归 Benchmark。Evaluation 不允许复制另一套路由逻辑。

## 2. 创建 Evaluation Run

创建 Run 时必须明确选择/记录：

- Dataset；
- Config Release（默认 Active，也允许选择历史 Release）；
- Model Config Override（可选；未选则使用 Release 默认模型）；
- Repeat：1 / 3 / 5；
- Worker Concurrency。

Run 创建后立即冻结 dataset hash、release id、config snapshot hash、release fingerprint、effective model config id/hash/snapshot、repeat_count 和 worker concurrency。后续 Active Release 或 Model Config enabled 状态变化不得改变该 Run。

## 3. Excel 输入

产品列：

- 用例编号
- 用户原话
- 期望一级路由
- 期望二级意图（可选）
- 期望追问内容/目标（可选）
- 备注

安全类统一通过期望一级路由映射 `safety`，不增加重复安全字段。

导入映射规则：
- 一级 Route 接受 `route.name` 或 `route.zh`；
- 二级 Intent 接受 `intent.name`、`intent.zh` 或 `intent.aliases`；
- 非训练业务行：二级 Intent 找不到匹配或匹配到多个对象 → 导入阶段返回可读错误（含行号、原值），不进入模型执行；
- 非训练业务行：若二级 Intent 所属 route 与“期望一级路由”不一致 → 导入阶段报错（行号 + 两者的值），避免评估集自相矛盾；
- 训练业务行：二级 Intent 不参与判定；能匹配就保存，匹配不上只记 warning（行号、原值），不阻断导入；
- 初始 Bootstrap 已覆盖 Excel 模板“期望二级意图”下拉的全部 39 个值（见 docs/03 §11），自带样例/模板填写不应出现导入错误；这是 TASK-301 的测试用例。

## 4. 自动判定

### Training

只比较一级 Route。

### 其他

- Route 必须一致。
- Expected secondary intent 非空时，固定比较 `actual.intents[0].name`（Top-1）。即使 expected 出现在后续候选但 Top-1 不同，仍判 `INTENT_MISMATCH`；额外候选只展示用于诊断。
- Expected clarification target 非空：要求 `need_clarification=true`；为空：要求 `need_clarification=false`。两种方向都纳入 Clarification Trigger Accuracy。
- Clarification 文本和“期望追问目标”同时展示，供人工检查；一期不引入 LLM-as-Judge，不对自然语言语义做不可控自动评分。

## 5. 指标

主 Benchmark 指标按每个 Case 的 `repeat_index=0` 计算，避免 repeat 1/3/5 改变同一 Dataset 的准确率权重；额外 repeat 仅用于 Stability/Route 分布。

- Overall Route Accuracy
- 一级 Route Confusion Matrix（Expected × Actual）
- Per-route Precision / Recall / F1
- Macro-F1（基于一级 Route，可用于 Run 对比）
- Safety Route Recall
- Secondary Intent Accuracy
- Clarification Trigger Accuracy
- JSON Schema Valid Rate
- Avg/P95 Latency
- Error Rate
- Route Stability Rate（repeat > 1）：同一 Case 的所有 repeat 一级 Route 完全一致则该 Case stable，同时展示各 Route 次数/占比

## 6. Run 对比 / 回归

仅允许对 `dataset_hash` 相同的两个 Run 做直接 A/B 对比。页面至少展示：

- Run A/B 的 Release、Prompt/config hash、effective Model Config；
- Overall Route Accuracy、Macro-F1、Per-route P/R/F1 差异；
- 一级 Route Confusion Matrix 并排或差异视图；
- 逐 Case 翻转：`PASS -> FAIL/ERROR` 标记 regression，`FAIL/ERROR -> PASS` 标记 improvement；
- repeat > 1 时，每个 Case 额外展示 `passed_repeats / repeat_count` 与 Route 分布，Run 对比本身不把 repeat 当作额外 Benchmark 样本。

Case 聚合状态规则：任一 repeat 为执行 ERROR -> `ERROR`；否则全部 repeat PASS -> `PASS`；其余 -> `FAIL`。

## 7. Evaluation Run 可复现条件

Run 必须绑定：

- dataset_id/version/hash
- config_release_id + config_snapshot_hash + release_fingerprint
- effective model_config_id + model_config_hash + snapshot
- repeat_count
- worker concurrency
- created_at

每一次 Case execution 都产生真实 Trace。

## 8. Worker 可靠性

不使用 BackgroundTasks 作为唯一机制。

`evaluation_run` 记录：

- status
- progress
- heartbeat_at
- claimed_by
- error

Worker 从 MySQL claim QUEUED Run。Case result 使用 `(run_id, case_id, repeat_index)` 唯一键，保证重试幂等。

服务启动时处理 stale RUNNING：可重新 QUEUE 未完成 Case，或按配置标记 FAILED；默认推荐恢复执行。

## 9. 输出

导出 Excel 保留原产品列，并增加：

- 模型一级路由
- 模型二级意图
- 模型追问
- need_clarification
- 是否通过
- 错误类型/说明
- request_id/trace_id
- 耗时
- repeat index

## 10. 错误分类

- ROUTE_MISMATCH
- INTENT_MISMATCH
- CLARIFICATION_TRIGGER_MISMATCH
- SCHEMA_INVALID
- MODEL_TIMEOUT
- MODEL_RATE_LIMIT
- MODEL_PROVIDER_ERROR
- PARSE_ERROR
- INTERNAL_ERROR

## 11. 工程验收

- 100% Case 要么完成，要么有明确 error_code。
- 100% Case execution 在 Trace 保留期内可关联 Trace；过期后按 docs/07 §8 显示“Trace 已过期”，结果行不丢失。
- Run 可在 Pod 重启后恢复或明确终止状态。
- 300 条级别评估集可稳定执行，不压垮 Runtime/Provider。
