# 09 参考项目与采用策略 — v1.2.4

> 调研时间：2026-10-12。目标是借成熟实现降低核心功能开发风险，不 Fork 大平台。**许可证/活跃度不作为本项目是否“值得参考”的决定因素，但不得复制无明确授权的源码。**

## 0. 参考优先级（强约束）

实现冲突时按以下优先级处理：

1. 本项目 `AGENTS.md`、`docs/*`、当前 Task Contract；
2. OpenAI Python SDK 官方仓库/README + Alibaba Model Studio/Qwen 官方文档；
3. 本文列出的“局部参考项目”；
4. 其他博客/示例。

**外部项目从来不是本项目的规范来源。** 尤其 retry、async、Trace、错误码、Release/Evaluation 语义不得因为参考仓库的实现而改变。

## A. Provider / Structured Output：必须阅读官方依据

### 1. `openai/openai-python`（官方 SDK）

GitHub：`https://github.com/openai/openai-python`

TASK-102 必须阅读 README 中 Async、Retries、Timeouts、Request IDs/Raw Response 相关章节，并以官方 SDK 当前行为为准：

- SDK 默认 `max_retries=2`；本项目必须显式 `max_retries=0`，所有 retry 只由 `QwenProvider` 管理；
- SDK 默认 timeout 很长（当前官方实现/README 为 10 分钟），本项目必须显式设置生产 timeout；
- FastAPI async 调用链优先使用 `AsyncOpenAI`，禁止把同步 client 直接放进 async event loop；
- SDK 提供公开 `_request_id`，也支持 `with_raw_response` 获取原始响应信息；Qwen OpenAI-compatible 接口是否提供可用 request-id/header **不得假设**，由真实 Qwen smoke test 实测，拿不到时允许 null；
- 一次真实 HTTP 模型请求必须对应一条 `LLMAttempt`。

**采用：最高。** SDK 行为以官方仓库为实现依据。

### 2. Alibaba Model Studio / Qwen Structured Output

官方文档：

- `https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions`
- `https://help.aliyun.com/en/model-studio/qwen-structured-output`

采用规则：

- 优先 `json_schema + strict=true`，仅在所选模型明确支持时启用；
- 不支持 strict schema 时显式配置 `json_object`，禁止静默降级；
- `json_schema/json_object` 开启时 **不发送 `max_tokens`**，避免 JSON 被截断；
- 最终输出仍经过 Pydantic/business validation。

**采用：最高。** Qwen 行为以官方文档和真实 smoke test 为准。

## B. 小型分类服务：只参考局部，不再作为“必读底座”

### 3. `sohaggain/ai-text-classification-api`

GitHub：`https://github.com/sohaggain/ai-text-classification-api`

可参考：

- `src/services/classifier.py`：Provider 单一入口、Structured Output、typed errors 的模块边界；
- `src/models/schemas.py`：Pydantic request/response contract；
- `src/api/routes/classify.py`：薄 API 层；
- `src/core/config.py`：typed settings；
- 单元/集成测试的 provider mock/dependency override 组织。

**明确禁止照抄两点：**

1. 该项目 `classifier.py` 使用 Tenacity 进行多次 retry，同时 `OpenAI(...)` 未显式设置 `max_retries=0`。OpenAI SDK 自己默认还会 retry，可能产生双层重试，违反“一次 HTTP = 一条 Attempt”的 Trace Contract。
2. 它使用同步 `OpenAI` client；本项目 FastAPI async 调用链优先采用异步 SDK。

**采用：中。** 只学模块边界、错误分类、测试组织，不学 retry/client 细节。

### 4. 删除：`manikantaoruganti/LLM-Prompt-Router-for-Intent-Classification`

从 Codex 阅读清单删除。实测源码中 Provider/解析异常会被直接转换为 `unclear`，还用 `print` 记录错误，Router 同时夹带回复生成，与本项目“基础设施错误必须显式失败、IntentService 不生成业务回答”的 Contract 冲突，参考价值低于噪音成本。

## D. Trace / Diff 参考

### 8. `open-telemetry/semantic-conventions-genai`

GitHub：`https://github.com/open-telemetry/semantic-conventions-genai`

只参考 LLMAttempt 字段命名/语义，例如：

- `gen_ai.provider.name`
- `gen_ai.request.model`
- `gen_ai.request.temperature` / `gen_ai.request.max_tokens`
- `gen_ai.response.id` / `gen_ai.response.finish_reasons`
- `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens`

本项目数据库字段名不要求机械改成 OTel key；目的是避免自行发明相反语义。**一期不要求接入 OpenTelemetry SDK/Collector。**

### 9. `benjamine/jsondiffpatch`

GitHub：`https://github.com/benjamine/jsondiffpatch`

它支持对象 deep diff、HTML/annotated formatter、长文本字符级 diff。TASK-202 可将它作为前端 Trace Diff 的优先候选，减少自写 diff 算法。

采用条件：

- 先在 Vue/Vite 中做最小兼容验证；
- 只负责展示层 diff，不改变后端 Trace/Replay Contract；
- 若引入，固定依赖版本并加组件测试；若不兼容，继续使用后端结构化 diff flags + 简单文本高亮，不因此阻塞 TASK-202。

### 10. `langfuse/langfuse` / `Arize-ai/phoenix`

仅参考 trace/generation/dataset/run 的概念关系和诊断页面信息层次。**一期不部署这些平台，也不增加 ClickHouse/重型 LLMOps 基础设施。**

## E. FastAPI / 测试 / 部署工程参考

### 11. `zhanymkanov/fastapi-best-practices`

GitHub：`https://github.com/zhanymkanov/fastapi-best-practices`

作为工程指南阅读：

- async route 中不要直接执行 blocking I/O；
- sync SDK 若无法避免，应隔离到 threadpool；本项目优先使用 async SDK；
- settings 拆分、Alembic、测试 client、ruff 等工程习惯。

它是“检查清单”，不是项目脚手架。

### 12. `fastapi/full-stack-fastapi-template`

GitHub：`https://github.com/fastapi/full-stack-fastapi-template`

只参考 pytest、CI/GitHub Actions、Docker/Compose 的组织方式。其 React/PostgreSQL/SQLModel 等技术选型与本项目不同，**禁止把模板整体搬进项目**。

### 13. 不采用：FastapiAdmin / Rasa 作为一期底座

- FastapiAdmin 会引入 Redis/RBAC 等超出一期范围的依赖；5 个研发页面直接 Vue3 + Element Plus 更轻。
- Rasa 不作为 Runtime/评测底座；最多以后参考 NLU 报告形态，不改变当前 LLM IntentService 路线。

## H. 采用原则

1. 参考项目只解决“怎么少踩坑”，不改变本项目范围。
2. 官方 SDK/Provider 文档高于第三方示例。
3. 不因某参考项目存在依赖，就引入该依赖。
4. 第三方实现与本项目 Contract 冲突时，以本项目为准并在 Task 输出中注明差异。
5. 禁止复制会破坏本项目 retry、错误、Trace、async 语义的实现。
6. 外部源码复制必须符合许可证；许可证/活跃度本身不决定“能否参考其设计思路”。
