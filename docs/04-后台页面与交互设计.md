# 04 后台页面与交互设计

## 1. 一级菜单

保持 5 个菜单：

1. 单条调试
2. 批量测评
3. 调用观测
4. 配置中心
5. 服务状态

页面目标是研发诊断，不建设通用 LLMOps 平台。

## 2. 单条调试

输入：

- text
- release（默认 Active）
- model config override（可选）
- repeat 1/3/5

结果：

- route / intents / slots / risk
- clarification
- Runtime JSON
- reason_summary/evidence（明确标记 Debug Only）
- 每次执行稳定性分布

调试详情：

- Config Release
- Effective Model Config
- Final Prompt
- Provider Attempts
- Raw Request/Response
- Parsed/Validation
- Timeline
- Token/Latency/Error

## 3. 批量测评

流程：

```text
上传 Excel -> 生成 Dataset -> 创建 Run -> Worker 执行 -> 看指标/FAIL -> Trace -> 导出
```

页面显示：

- Run status/progress
- Overall Route Accuracy
- 一级 Route 混淆矩阵
- Per-route Precision / Recall / F1
- Safety Route Recall
- Secondary Intent Accuracy
- Clarification Trigger Accuracy
- Avg/P95 latency
- Stability
- FAIL/ERROR 筛选
- Run 对比：仅同一 `dataset_hash`；逐 Case 展示 A/B 状态、PASS→FAIL/ERROR 回归、FAIL/ERROR→PASS 改善；repeat>1 时同时展示各 Run 的 repeat 通过数与 Route 分布

## 4. 调用观测

列表字段：时间、request_id、trace_id、source、input、route、model、release、latency、status。

过滤：request_id、关键词、route、intent、model、release、时间、status。

详情：

- Runtime Result
- Config/Model Snapshot
- Final Prompt
- LLM Attempts
- Raw Request/Response
- Parsed/Validation
- Reason/Evidence
- Timeline
- Error

### Replay

- Historical snapshot replay
- Current active release replay
- repeat 1/3/5
- 新建 trace_id，记录 parent_trace_id

### Diff

选择两个 Trace，比较：

- input
- release/hash
- prompt hash/final prompt
- effective model config
- provider metadata
- attempt count/detail
- raw response
- parsed result
- final result

Diff 重点是定位“差异首次出现的位置”，不建设复杂文本审阅平台。

## 5. 配置中心

UI 仍按业务分区：

- Intent
- Slot
- Enum/Alias
- Route
- Prompt Template
- Model Config
- Release

底层 Draft 可以是单个 JSON 文档，不要求每个分区一张数据库表。

操作：编辑、保存 Draft、校验、Prompt Preview、Publish、History、从历史版本创建 Draft。

## 6. 服务状态

`/status` 进入时自动加载，支持手动刷新，展示检查时间、加载失败及上次结果已过期提示。

- 就绪检查：数据库与表结构、当前发布配置、默认模型分别显示“已就绪 / 未就绪 / 无法检查”和原因。运行配置检查复用 Runtime 的业务配置、模型参数和凭据加载校验，不发起模型请求。
- 当前配置：生效版本、发布说明、发布时间、默认模型名称，提供配置发布和模型管理入口。默认模型展示不依赖是否存在已发布配置。
- 调用概览：默认统计线上请求，可切换调试、重放、评测来源；显示 24 小时请求数、失败数、取消数和失败率（失败数 / 请求数）。仅统计已保存的 Trace，零请求的失败率为空。
- 模型调用耗时：使用请求内所有模型调用尝试的累计时间，包含重试调用，不含排队、重试等待及其他处理时间；展示有效样本数、平均值和最近秩 P95。所有有耗时的请求均参与，不限成功状态。
- 调用定位：查看全部或失败请求时，将来源和统计时间窗口带到调用观测；时间窗口为 UTC 的 `[start, end)`，界面按浏览器本地时间显示。观测页面可以清除筛选。
- 评测任务：当前全部排队数、运行数，不受调用来源或 24 小时窗口影响；运行数不等同于 Worker 健康检查。

`GET /api/admin/status/summary?source=runtime` 返回各检查项的 `state/code/message`、`checked_at/window_start` 和摘要。数据库未配置或某个检查失败时仍返回可读取的摘要，缺失统计使用 `null`，不伪造为零。`runtime_config_ready` 为 `null` 表示无法确认，`false` 表示存在明确的配置问题；`service_ready` 保持与 `/ready` 同一检查定义。每项检查有 5 秒超时，独立读取，整份报告不是跨表原子快照。

前端请求 15 秒超时，离开页面会取消请求；不自动轮询。状态 JSON 放在折叠详情中。

不建设 Prometheus/Grafana 管理台；平台已有监控可继续采集普通应用日志/指标。
